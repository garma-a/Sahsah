# Schema scenario review

Physical model updated by [ADR 0007](../adr/0007-consolidate-launch-schema.md): account rows own active-game claims and token balances; grants are direct ledger authorizations, settlements are order fields, and question state/result/feedback share `game_questions`. Scenario descriptions use these business concepts without requiring separate tables.

Updated v1.2, 2026-11-03. This table traces the service contracts; selected cases now have [executed SQL/reference-transaction coverage](validation/README.md). Full API/provider integration and deployed load remain untested. Q84–Q87 are accepted.

| Scenario | Proposed resolution and durable evidence | Boundary still requiring implementation |
| --- | --- | --- |
| Two devices start with the last token | Check authenticated start request UUID/digest first; lock room/accounts/claims/wallet; one accepted game, one debit, nonnegative bank. Room generation and active-account claim reject conflicting starts. | Consistent locks, exact request hash and atomic full start |
| Accepted start response is lost | Durable `games.start_request_id/digest` resolves the original game before a new claim/balance check; no second debit. | Never reallocate a new game from the same accepted request |
| Start is rejected halfway | Snapshots, roster, claims, ledger and wallet roll back together; unpaid lobby remains room data. | Transaction includes every local start effect |
| Admin edits while a game starts | Lock selected categories/packs consistently, validate publication/revision/media and copy one coherent set. Existing games retain text/config/assets. | Shared catalog lock order, revision recheck and immutable ready media |
| A replacement enters a completed pack | New logical question ID; earlier completion remains; current IDs flag Updated; group freshness checks all current IDs. | Set-based exposure anti-join and current/historical identity comparison |
| Two games share signed-in players | One active-account claim per signed-in starting participant, acquired with accepted start; no token charge for rejected conflict. | Old-game expiry finalized separately before retry |
| Open races ending/expiry | Same root game lock and fresh clock determine the first accepted transition. First opening sets sticky marker/exposures; terminal unopened game restores once. | Never clear opening marker; publish only after commit |
| Guest disconnects versus explicitly leaves | Disconnect preserves frozen participation. Explicit leave marks the historical seat, releases only its claim and stops future credit; reconnect credentials restore only eligible membership. | Serialize leave with open/resolve; no replacement seat in active game |
| Host takes over another device | Same account rotates current credential/generation; later old-controller mutations fail; no new debit. | Current authority checked for every command; no plaintext credential in receipts |
| Award response is lost | Command digest/result plus unique slot resolution/source score entry prevents another award, even if a retried payload changes winner. | Exact cap/default, actor and matching resolution/score values |
| Host corrects 600 to 400 | Append -200 with old/new totals and set team projection to 400; keep prior question awards/category results. | Game active, integer nonnegative target, projection and event commit together |
| 36th resolution and feedback | Last resolution automatically locks results/releases claims. Host feedback is a separate reveal-authorized resource, not a score command. | Q85 closes new/edited feedback after actual purge while retaining existing votes |
| Two genuine payments and repeated callbacks | All verified distinct transactions retained; one order settlement/grant/credit. Exact receipt digest dedupes deliveries without dropping later changed transaction facts. | Correct HMAC type, merchant mapping, eligible proof and staff extra-payment case |
| Checkout looks failed, then payment succeeds | Honor verified exact frozen order once; preserve any old closure/promo release in reconciliation. No automatic new grant for an already-settled order. | Inquiry of unsigned/uncertain fields; no fabricated closure proof |
| Refund/void notification arrives later | Record actual action/cumulative confirmed facts and original-parent relationship; typed settlement source excludes refund/void funding. Original grant remains; no automatic negative bank. | Inquiry ordering/conflicts and audited exceptional reconciliation |
| Gift claim races payment/phone change | Lock consistent accounts/order, preserve checkout/first-claim account binding and issue the source grant once. Buyer self-gift rejected. | Current verified ownership; no later phone lookup rerouting |
| Staff corrects gift phone | Only unbound/unclaimed gift, verified buyer request, self-gift recheck and unique audited correction. Once bound, no correction/rerouting. | Authorized Admin action/target and claim/correction serialization |
| Zero-cost order/retry | Actual fixed-bundle code/automatic campaign admission, local settlement, consumed use and available grant/bank credit commit once; no provider attempt. | Caps count held/consumed under promo lock; Q87 campaign-local phone marker prevents same-phone reset |
| Account deletion with a bank | Leave/end first, confirm exact bank, unique negative forfeiture if positive, clear/revoke personal access and schedule external cleanup; retain IDs/evidence. | Fresh Q86 funding clearance/review, exact consent and policy-governed PII cleanup |
| Outbox worker crashes | Committed source/work remain; expired lease is reclaimed, acknowledgments are fenced by token, handlers reload source state. | Unknown provider effects require inquiry; external actions are not exactly once merely because of SQL |
| Full game content reaches 12 months | Lock terminal root, remove its asset pins/copy payloads with markers, retain source IDs/results/progress; collect only genuinely unreferenced assets. | Cross-row purge completion, parent deadline, retained catalog/other references and Q85 feedback rule |
| Removed account tries immediate lobby rejoin | Removed membership/credential is ineligible; Q84 blocks the known account until host unblock, requiring a new membership. | Current-membership uniqueness, host-recorded unblock and revoked old credential |

The supplemental partial unique indexes include protection for active game/room, current signed-in room membership and open deletion request. The DBML exporter does not apply these automatically. See [supplementary SQL](postgresql-supplement.sql), [payment workflows](payment-workflows.md), [operations/retention](operations-and-retention.md) and [query planning](query-plan.md).

Native v1.1 adds proof replay across accounts, pending-to-purchased transition, encrypted-token intake before SKU discovery, bank-commit/completion failure, optional historical amount, unmatched first verified claim and later store refund. Required outcomes are traced in [native-store-billing.md](native-store-billing.md); these are not executed billing tests.

The [quality review](design-quality-review.md) records fixed source/proof gaps, ledger projection, deletion/purge boundaries, recurring-proof facts and measured index refinements. [Before-audit reproductions](validation/before-audit-reproductions.json) record two invalid funding/closure cases accepted by the v1.1 snapshot; the current suite rejects both. Remaining boundaries in this table are future service integration responsibilities rather than unanswered product questions.
