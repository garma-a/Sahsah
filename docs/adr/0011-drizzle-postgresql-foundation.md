# Use stable Drizzle with reviewed PostgreSQL migrations

Accepted 2026-11-04. The user selected Drizzle ORM for the agreed 39-table design, chose the latest stable ORM 0.45.4 / Kit 0.31.11 rather than the 1.0 release candidate, and included the minimal database foundation in NestJS 12.3.3. The user also removed the unapproved 10% gift default; initializing shop settings requires an explicit percentage.

The existing design includes PostgreSQL-specific deferrable relationships, private security-definer functions, partial indexes, ledger projection and financial/lifecycle constraint triggers. SQL-only access would preserve these directly; automatic ORM synchronization would risk losing behavior. Keep typed Drizzle schema modules and reviewed versioned SQL together. Model partial indexes in Drizzle, preserve unsupported deferral/functions/triggers in a custom migration, and create referenced unique indexes before adding foreign keys. The application layer has no dependency on parent/sibling application source.

Use node-postgres for the single long-running NestJS service, with a bounded pool and an explicit transaction boundary that commits before acknowledgement and handles deferred commit failures. Use Drizzle's maintained migrator behind migration-history hash checks and a session advisory lock. Run schema commands explicitly with separate migration-owner credentials; the runtime uses restricted grants, verifies migration readiness and applies no DDL at startup. Development without database configuration retains the starter, while production requires a usable migrated database.

The trade-off is maintaining SQL behavior alongside the TypeScript snapshot and reviewing generated dependency order. This preserves the validated PostgreSQL contract and precise TypeScript access without replacing the database's integrity protections or introducing CRUD scaffolding for every table. The integration suite verifies actual migrations, the runtime role and transaction boundary in disposable PostgreSQL 18. Staff/player/provider/gameplay workflows remain separate increments.
