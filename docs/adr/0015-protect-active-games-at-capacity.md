# Refuse new allocations while preserving active games

Accepted 2026-11-05 in API-Q7/Q10/Q11. Close new-room, new-game/replay and new-guest admission at the requested 85% capacity boundary, using actual deployment limits and a measured gameplay envelope. Return 503 SERVER_AT_CAPACITY with Retry-After before new allocation or debit; preserve bounded existing-game commands, finish/leave, authorized reconnect/media and recovery of already accepted operations.

If required current pressure measurements are missing beyond a bounded grace period, pause new admission until fresh healthy measurements and a lower recovery threshold permit reopening. This trades temporary newcomer availability for headroom protecting games already admitted; it does not end games, revoke seats or authorize automatic paid scaling. Keep pressure checks cheap, reserve allocations atomically, bound protected queues/reconnects and rebuild occupancy after restart. Railway's aggregate plan/network maxima and spending cutoffs do not establish safe game capacity. See [the admission design](../api/admission-control.md) for initial tunable thresholds/windows; deployment measurements and implementation remain outstanding.
